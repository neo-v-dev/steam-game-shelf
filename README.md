# Steam Game Shelf 🎮

[English README is here → docs/README.en.md](docs/README.en.md)

Steam の所有ゲーム一覧を取得して、GitHub Pages で公開できるサイトを自動生成するテンプレートです。配信者が「持っているゲーム」を視聴者に公開する用途を想定しています。

- **無料で動作**: GitHub の無料枠(Actions + Pages)だけで完結。サーバー不要。
- **自動更新**: 毎日自動でゲームリストを更新。手動更新も1クリック。
- **管理ページ**: カード(サムネイル)表示(デフォルト)とリスト表示を切り替えながら、表示/非表示・プレイ済みタグ・時間表示・配信リンク・サイト設定をブラウザから編集可能。検索絞り込みとソート(名前順/プレイ時間順/最近プレイした順/発売日順/開発元順/販売元順)、プレイ時間・最終プレイ日・発売日の確認もできる。
- **非表示設定**: 見せたくないゲームをサイトから除外可能。
- **プレイ済みタグ**: 初期値はプレイ時間から自動判定。サイト上でバッジ表示&絞り込みできる(サイト全体で非表示にすることも可能)。
- **プレイ時間の表示制御**: サイト全体の一括OFFと、ゲームごとの個別OFFの両方に対応。
- **配信リンク**: ページ上部にチャンネルリンク、各ゲームに配信/動画リンク(▶アイコン)を設定可能。対応は YouTube(`youtube.com` / `youtu.be`)、Twitch(`twitch.tv`)、niconico(`nicovideo.jp` / `nico.ms`)のみで、閲覧者を有害なリンクから守るための制限です。
- **日本語 / 英語**: 閲覧者がサイト上で切り替え可能。
- **日本語ゲーム名**: 邦題を自動取得し、日本語表示時は邦題で表示(検索は原題・邦題の両方にヒット)。

## 必要なもの

- GitHub アカウント
- Steam アカウント(プロフィールの「ゲームの詳細」が**公開**設定であること)
- Steam Web API キー(無料。下記手順で取得)

## セットアップ手順

### 1. リポジトリを作成

このリポジトリの上部にある **「Use this template」→「Create a new repository」** をクリックし、自分のリポジトリを作成します(Public を選択してください。無料プランでは Public リポジトリのみ GitHub Pages が使えます)。

### 2. Steam API キーと SteamID を用意

- **APIキー**: https://steamcommunity.com/dev/apikey で取得(ドメイン名は `localhost` などでOK)
- **SteamID64**: 17桁の数字。自分のプロフィールURLが `steamcommunity.com/profiles/7656...` ならその数字。カスタムURLの場合は https://steamid.io で調べられます。
- **プライバシー設定**: Steam の「プロフィールの編集 → プライバシー設定」で「ゲームの詳細」を**公開**にしてください。非公開だと API が一覧を返しません。

### 3. Secrets を登録

作成したリポジトリの **Settings → Secrets and variables → Actions → New repository secret** で以下の2つを登録します。

| Name | 値 |
|---|---|
| `STEAM_API_KEY` | 手順2で取得した API キー |
| `STEAM_ID` | あなたの SteamID64(17桁の数字) |

### 4. GitHub Pages を有効化

**Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** に設定します。

### 5. 初回のリスト取得

**Actions タブ → 「Update game list」→「Run workflow」** を実行します。完了すると `data/catalog.json` に全所有ゲームの一覧がコミットされます。このとき、README のデモ紹介文の削除とあなたのサイトへのリンクの追記も自動で行われます(該当区間は自動管理のため手で編集する必要はありません)。

この時点ではまだ `published: false` のため、サイトには「準備中」画面のみが表示されます。

### 6. 非表示設定(公開前の確認)

**管理ページを使う方法(推奨)**: `https://<ユーザー名>.github.io/<リポジトリ名>/admin.html` を開き、下記「管理ページ」の手順でアクセストークンを設定すると、カードをクリックして表示/非表示を切り替えられます(初期表示はカード表示。リスト表示に切り替えるとチェックボックスでも操作できます)。

**JSON を直接編集する方法**: `data/catalog.json` を GitHub 上で開いて(鉛筆アイコンで編集)、見せたくないゲームの `"visible": true` を `"visible": false` に変更してコミットします。

### 7. 公開

管理ページの「サイトを公開する」にチェックを入れて保存するか、`config/settings.jsonc` の `"published"` を `true` に変更してコミットすると、サイトが公開されます。URL は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。

以降は毎日自動でリストが更新されます。新しく買ったゲームは `default_visibility` の設定に従って表示/非表示されます(買ってすぐ見せたくない場合は `default_visibility: false` にしておき、手動で `visible: true` にする運用がおすすめです)。

## 管理ページ

`https://<ユーザー名>.github.io/<リポジトリ名>/admin.html` で、以下をブラウザから編集できます(JSON 編集不要)。デフォルトは公開ページと同じ見た目の**カード(サムネイル)表示**で、**リスト表示**にも切り替えられます(切り替えた選択は記憶されます)。

- ゲームごとの**表示/非表示**(リスト: チェックボックス / カード: カードをクリック。検索絞り込みつき)
- **ソート**(名前順 / プレイ時間順 / 最近プレイした順 / 発売日順 / 開発元順 / 販売元順。検索絞り込みと併用可。リスト・カード両方に反映。管理ページではスイッチOFFでも選択肢は消えません。発売日順は表示のON/OFFスイッチが無いため常に選択肢にあります。開発元順/販売元順は、同じ開発元(販売元)内では直前に選んでいたソート(未選択時は名前順)で並びます)
- 各ゲームの**プレイ時間・最終プレイ日・発売日・開発元**の確認(リスト行のメタ情報、カードは本文にまとめて表示。最終プレイ日は未記録なら省略、プレイ時間0は「未プレイ」、発売日は取得できたゲームのみ、開発元は取得できたゲームのみ)
- ゲームごとの**プレイ済みタグ**(チップをクリック)
- ゲームごとの**プレイ時間表示**(「時間表示」チップでOFFにすると、そのゲームだけプレイ時間を隠せる)
- ゲームごとの**配信/動画リンク**(URLを入力すると、公開ページのカードに▶アイコンが表示される)
- サイト設定: **サイト名 / 初期表示言語 / デザイン / 「カードの表示項目」(プレイ時間表示・プレイ済みタグ・最終プレイ日表示・開発元表示、それぞれサイト全体のON/OFF) / チャンネルURL**
  - 「カードの表示項目」の各スイッチはいわば一括スイッチで、OFFにしてもゲームごとの設定は保持されます。カードだけでなく、上部の統計(プレイ時間の合計)や絞り込みセレクト(プレイ済み/未プレイ)にも影響します
  - チャンネルURLを設定すると、公開ページ上部に配信チャンネルへのリンクボタンが表示されます
  - デザインを切り替えると管理ページの配色がその場でプレビューされます(保存するまでサイトには反映されません)。選択肢は `site/themes/` に追加したCSSで増やせます(下記「デザインの追加方法」)
- サイトの**公開/準備中**の切り替え

保存すると GitHub にコミットされ、1〜2分でサイトに反映されます。

**初回設定(アクセストークン)**: 編集にはあなたの GitHub アクセストークンが必要です。ページ自体は誰でも開けますが、トークンがなければ保存はできません。

1. GitHub の **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token** を開く
2. **Repository access** で「Only select repositories」→ 自分のリポジトリのみを選択
3. **Permissions → Repository permissions → Contents** を「Read and write」に設定して作成
4. 管理ページにリポジトリ名(`owner/repository`)とトークンを入力して「読み込む」

「読み込む」を押すと、接続セクションのボタン直下に進行状況(トークンを検証しています…→データを読み込んでいます…)とエラーが表示されます。トークンが無効・対象リポジトリが誤り・書き込み権限がない場合は、この時点でエラーが表示され読み込みは行われません(保存するまで気づけない、という問題の是正です)。まだ「Update game list」を一度も実行していない場合は data/catalog.json が見つからない旨のエラーとともに「Actions を開く」ボタンが表示されるので、そこから実行ページに移動できます。

トークンはブラウザの localStorage にのみ保存され、api.github.com 以外には送信されません。共用PCでは使用後にブラウザのサイトデータを削除してください。また、GitHub Pages の `<ユーザー名>.github.io` は同じユーザー名の他のリポジトリとオリジンを共有するため、同一オリジンの別ページの JavaScript からこの localStorage が理論上読み取られる可能性があります(通常は問題になりませんが、同じ `<ユーザー名>.github.io` 配下で信頼できないコードを公開している場合はご注意ください)。`admin.html?demo=1` でサンプルデータの操作を試せます(保存は無効)。

## プレイ済みタグ

各ゲームに「プレイ済み」タグを付けられます。初回はプレイ時間が1分以上あれば自動でONになり、以降は管理ページ(または `data/catalog.json` の `played`)で自由に変更できます(手動設定は自動更新で上書きされません)。サイトではバッジ表示と「プレイ済み / 未プレイ」絞り込みに使われます。管理ページの「カードの表示項目」でサイト全体のプレイ済みタグ表示をOFFにすると、バッジと絞り込みの両方が非表示になります(ゲームごとの設定は保持され、ONに戻すと元どおり反映されます)。

## 設定項目

`config/settings.jsonc` で以下を変更できます(ファイル内コメント参照)。

- `published` — サイトの公開/準備中
- `site_title` / `site_description` — サイトのタイトルと説明
- `default_lang` — 初期表示言語(`ja` / `en`)
- `theme` — サイトの配色(デザイン)。`site/themes/` 内のCSSファイル名(拡張子なし)を指定します。存在しないIDを指定した場合はビルド時に `dark` にフォールバックします
- `show_playtime` / `show_played` / `show_last_played` / `show_developer` — プレイ時間・プレイ済みタグ・最終プレイ日・開発元の表示(`show_played` は絞り込みセレクトの表示にも影響。OFFにした項目は公開ページのソート選択肢からも自動的に除外され、名前順しか残らない場合はソートセレクト自体が非表示になります)
- `channel_url` — 配信チャンネルのURL(ページ上部にリンク表示)
- `default_visibility` — 新規取得ゲームをデフォルトで表示するか
- `fetch_japanese_names` — 日本語のゲーム名を取得するか

### 日本語ゲーム名について

Steam API が返すゲーム名は原題(多くは英語)のため、別途ストア API から邦題を取得して `data/catalog.json` にキャッシュしています。ストア API のレート制限が厳しいため、**1回の更新で最大150件**ずつ取得します。所持数が多い場合、全件揃うまで数回の更新(日次自動更新または手動実行)がかかりますが、取得済みの分は再取得されません。すぐに揃えたい場合は Actions から「Update game list」を数回実行してください。

サイトのソートは邦題(あれば)または原題を対象に日本語照合(`localeCompare('ja')`)で行われます。**邦題がまだ揃っていないゲームは、揃うまで原題(多くは英語)でソートされます**。また、**漢字タイトルは読み仮名データを持たないため、五十音の読み順には並びません**(文字コード順に近い並びになります)。これは技術的な制約であり、将来的な改善予定はありません。

### ゲーム画像について

新しめのタイトルは appid からの推測URLに画像が無いことがあるため、邦題と同じタイミングでストア API から正式なヘッダー画像URLも取得し `data/catalog.json` にキャッシュしています(取得できない場合は推測チェーンにフォールバックします)。

### 開発元/販売元について

邦題・画像と同じタイミングでストア API から開発元/販売元(複数社ある場合は先頭の1社)を取得し `data/catalog.json` にキャッシュしています。取得できたゲームのみカードに開発元が表示され、ソートの「開発元順」「販売元順」で使われます(取得できていないゲームはソート末尾)。

### 発売日について

邦題・画像・開発元/販売元と同じタイミングでストア API から発売日を取得し `data/catalog.json` にキャッシュしています。発売日は表示・ソートともにON/OFFの設定がなく常に表示されます(取得できていないゲームは表示なし、ソートでは末尾)。未発売(coming soon)のゲームや、四半期表記("Q3 2026" 等)・年のみなど解析できない形式の場合は、日付順での比較には使われません。

### デザインの追加方法

サイトのデザインは `site/themes/` 以下のCSSファイル(1テーマ=1ファイル)で切り替えられます。標準で **default(ダーク)/ neon / hud / horror / pixel** の5テーマを同梱しています。一部テーマが使う表示フォント(Press Start 2P / DotGothic16 / Zen Old Mincho / Chakra Petch)は `site/fonts/` に woff2 を同梱しており(いずれも SIL Open Font License)、選択中テーマの分だけ読み込まれます。

1. `site/themes/` に新しいCSSファイルを追加します(例: `light.css`)。`:root { --sgs-bg: ...; --sgs-surface: ...; --sgs-text: ...; --sgs-accent: ...; --sgs-border: ...; --sgs-radius: ...; }` などのトークン(一覧は `site/base.css` 冒頭の既定値を参照)と、必要なら装飾の上書きを書きます。レイアウトなどの構造は `site/base.css` が担当するため変更不要です(`site/themes/default.css` を複製して書き換えるのが手早い方法です)。
2. `site/themes/themes.json` に `{ "id": "light", "label": "Light" }` のように1行追加します。
3. `config/settings.jsonc` の `"theme"` を追加したIDに変更するか、管理ページの「サイト設定 → デザイン」セレクトから選んで保存します。存在しないIDが設定された場合は `node scripts/build.mjs` 実行時に自動的に `default` にフォールバックします。

管理ページでは、デザインを切り替えるとその場でプレビューされます(保存するまでサイトには反映されません)。

## 取得できないゲームについて

Steam Web API(`GetOwnedGames`)の仕様上、以下のゲームは取得できません。

- **未プレイの無料ゲーム**: プレイ時間が一度も記録されていない無料ゲームは、API のレスポンスに含まれないことがあります。
- **ファミリーシェアで借りているゲーム**: 自分のライブラリではなく他アカウントの共有によるゲームは対象外です。

これは Steam API の既知の制約であり、本ツール側では回避できません。

## ⚠️ 非表示機能について(重要)

非表示設定は「このサイトに表示しない」機能であり、**完全な秘匿ではありません**。

- Steam API の仕様上、プロフィールの「ゲームの詳細」を公開にする必要があるため、Steam プロフィールを直接見れば所有ゲームは分かります。
- また、このリポジトリは Public のため、`data/catalog.json`(非表示フラグ含む)は閲覧可能です。

「配信で見せるゲーム棚を整理する」用途としてお使いください。所有自体を知られたくないゲームがある場合はご注意ください。

## ローカルでの実行(開発者向け)

```bash
# リスト取得
STEAM_API_KEY=xxx STEAM_ID=7656... node scripts/update.mjs

# サイトデータ生成(site/data/games.json に加え、テーマCSSも site/data/theme.css に生成されます)
node scripts/build.mjs

# プレビュー
npx serve site   # または python3 -m http.server -d site 8000

# テスト(依存パッケージなし。node:test 標準機能のみ使用)
node --test
```

Node.js 20 以上が必要です。依存パッケージはありません。
